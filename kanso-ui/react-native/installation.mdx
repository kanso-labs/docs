
## Peer dependencies

Beside `react` and `react-native`, the package needs:

| Package | What it does here |
| --- | --- |
| `react-native-reanimated` | The ripple a pressed control draws, and the corner a button morphs between |
| `react-native-worklets` | What Reanimated runs on |
| `react-native-svg` | The icons the controls show |
| `react-native-safe-area-context` | Insets that keep what the library draws above the screen clear of a notch, the status bar and the home indicator |
| `react-native-gesture-handler` | Carrying a switch's handle across its track when it is dragged |

<Tabs>
  <Tab title="Expo">
    ```bash
    npx expo install react-native-gesture-handler react-native-reanimated react-native-safe-area-context react-native-svg react-native-worklets
    ```

    That installs the versions the SDK ships with, and Expo's Babel preset compiles the package's animations.
  </Tab>
  <Tab title="Bare React Native">
    Install the same five packages, then follow Reanimated's install guide, which adds `react-native-worklets/plugin` to the app's Babel configuration.
  </Tab>
</Tabs>

<AccordionGroup>
  <Accordion title="Safe-area insets">
    The insets come from safe-area-context's `SafeAreaProvider`, which Expo Router already puts around an app; elsewhere, wrap the app in one. Without it, the library keeps to the window's edge.

    `AppBar` and the panes of a `ListDetail` are the exception: each measures its own insets through `SafeAreaView`, so it clears only the edges it actually meets, and needs no provider on a device.
  </Accordion>
  <Accordion title="Gesture Handler">
    Gesture Handler 2 and 3 both satisfy the peer. `Switch` and `Slider` each draw Gesture Handler's root view around their own track, so an app need not wrap itself in `GestureHandlerRootView` for them, and one that already does loses nothing.
  </Accordion>
  <Accordion title="The keyboard">
    `react-native-keyboard-controller` is an optional peer. A `Sheet`, a `Dialog` and a `SearchView` keep what they hold above the software keyboard, and on Android they need it to: React Native draws edge to edge there, so the keyboard covers the window rather than shrinking it, and each of the three is a `Modal`, a window of its own, whose keyboard Android reports to nothing React Native listens to. Install it, and mount its provider at the root of the app:

    ```bash
    npx expo install react-native-keyboard-controller
    ```

    ```tsx
    import { KeyboardProvider } from 'react-native-keyboard-controller'

    export default function Root() {
      return (
        <KeyboardProvider navigationBarTranslucent statusBarTranslucent>
          <App />
        </KeyboardProvider>
      )
    }
    ```

    Without it, iOS keeps the overlays above the keyboard all the same, and Android does so only for a field in the app's own window. A screen of the app's own is the app's to keep clear, with the controller's `KeyboardAwareScrollView` or `KeyboardAvoidingView`.
  </Accordion>
  <Accordion title="Fonts">
    `expo-font` is an optional peer. Without it the mono family draws in the platform's monospaced face, and every other type role in the system font. See [Fonts](/kanso-ui/react-native/theming#fonts).
  </Accordion>
</AccordionGroup>

## The root

The outermost `ThemeScope` hosts what the library draws above the screen, such as sheets and snackbars, so it belongs at the root of the app and fills it:

```tsx
import { ThemeScope } from '@kanso-labs/react-native-kanso-ui'

export default function App() {
  return (
    <ThemeScope style={{ flex: 1 }}>
      <Screen />
    </ThemeScope>
  )
}
```
